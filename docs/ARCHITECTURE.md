## Текущая реализация: Next.js, 30.09.2026

По прямому заданию владельца рабочий сайт перенесён на **Next.js 16.3.7 / React 19.3.0**, App Router. `npm run dev`, `npm run build` и `npm start` используют Next.js. Публичные страницы предрендерятся на сборке. По последующему заданию владельца адреса очищены: главная `/`, каталог `/objects/`, услуги `/services/klopy`, объекты `/objects/dentistry`, памятка `/instructions`, панель `/admin`. Прежние известные URL с `.html` перенаправляются кодом 308; параметры запроса и якоря сохраняются. Неизвестные и ранее удалённые страницы возвращают 404.

Каталог использует завершающий `/`, потому что на nginx/Plesk существует физическая папка `objects/`. В статической публикации каталог лежит в `objects/index.html`: nginx может обслужить его напрямую, без цикла `/objects` ↔ `/objects/`. Изображения каталога и общие ресурсы имеют пути от корня. `tools/export_hosting.py` проверяет готовые файлы через `tools/audit_hosting.py` до создания архива. Next.js сохраняет то же поведение, а остальные страницы остаются без завершающего `/`. Ссылки `.detail-copy .inline-link` подчёркнуты и имеют видимый клавиатурный фокус.

Ссылка передаётся установленному приложению без принудительного перехода в WhatsApp Web; разрешение на открытие приложения зависит от браузера и ОС. Переключатель RU/KZ обновляет текст шаблона. Постоянная кнопка справа (`QuickContact`) раскрывает выбор звонка или чата, поддерживает клавиатуру, Escape и закрытие при клике снаружи; при открытии формы становится неактивной. Обе формы используют общий обработчик валидации и отправки; корпоративная заявка получает `requestType: business`. Значения двух форм независимы и сохраняются после перехода в WhatsApp. Сообщение отправляет сам посетитель.

Править новые страницы и общий интерфейс нужно в JSX и `lib/`, а не в старых HTML/JS. Новую страницу также добавить в реестр, список маршрутов и SEO-данные. Обычные ссылки оставлены с полным переходом: это сохраняет относительные адреса, историю браузера и существующую модель инициализации. Обработчики и таймеры подключаются и снимаются через React lifecycle; второй обработчик формы не добавлять.

Стили `QuickContact` импортируются самим React-компонентом и входят в CSS Next.js с хешем в имени. Кнопка не зависит от сохранённого в браузере `/css/theme.css` или вложенного `@import`; её SVG также имеют явные размеры. Регрессионный тест проверяет старый theme CSS и недоступный отдельный CSS компонента на всех семействах страниц.

Исходные HTML, `js/`, `server.js`, `server.py` и прежние генераторы сохранены для истории и открытия статической версии с диска. Они **не участвуют в Next.js build**. `npm run legacy:serve` запускает только прежнюю версию. `tools/migrate-next.py` — однократный импорт, запрещает перезапись существующих JSX; повторно запускать его для обновления сайта не нужно. `build_catalog.py`, `sync_layout.py` и `seo.py --apply` меняют только прежнюю статическую версию и больше не являются способом редактирования работающего Next-сайта.

Проверки: `npm run build`, `npm test` (на production Next, выделенный порт 8082), `python tools/audit_next.py http://127.0.0.1:8080`. Старый `audit_public.py` продолжает проверять сохранённый HTML. Тесты API используют отдельный временный файл, не клиентские заявки. Панель сохраняет прежнюю локальную модель: статусы и удаление пишутся в localStorage, не синхронизируются с серверным списком. API хранит `leads.json` вне публичных ресурсов; `LEADS_FILE` позволяет указать постоянный том. Это по-прежнему не защищённая многопользовательская CRM.

Полный отчёт и порядок запуска: [NEXT_MIGRATION.md](NEXT_MIGRATION.md).

## Профиль услуг и памятка, 30.09.2026

По заданию владельца из текущей Next.js-версии исключены самостоятельный клининг, дезодорация, выведение кротов и отлов змей. Их маршруты удалены из `content/routes.json`, `content/pages.js`, `content/seo.json` и sitemap. Исторические HTML и неиспользуемые JSX сохранены в рабочей папке, но не входят в реестр или новую публикацию. На статическом хостинге старые четыре HTML-файла нужно удалить отдельно.

`content/pages/instructions.jsx` — памятка `/instructions.html`; `content/guide-translations.json` — полный RU/KZ-текст, подключённый к действующему переключателю через `lib/site-interactions.js`; `css/treatment-guide.css` — стили только компонента памятки; `images/guides/before.svg`, `after.svg` — декоративные иллюстрации с текстовыми подписями. Ссылки доступны в карточке главной и общем подвале. Новых обработчиков форм или переключателя языка нет.

ROADMAP и критерии готовности: `ROADMAP.md`. Дополнительные проверки: `tests/treatment-guide.spec.js`. Браузерный обход берёт актуальный реестр маршрутов, а не архивные HTML. Проверка SEO сопоставляет предложения только с карточками услуг: ссылка на инструкцию не является коммерческим предложением.

## Общий каркас

Шапка, подвал, `.bmenu`, `.mbb` и `.modal` берутся из `index.html`. `sync_layout.py` копирует их на `objects.html`, `objects/*.html`, `services/*.html`, преобразует ссылки в `../…` и якоря в ссылки на главную. Также нормализует окончания строк/хвостовые пробелы и удаляет старый встроенный обработчик `openServiceModal` на вложенных страницах. Поэтому даже синхронизация требует проверки diff.

Внутренние страницы используют `.detail-hero`, `.detail-section`, `.detail-grid` и `.catalog-cta`. У услуг в первом блоке фотография; у отраслей и объектов — информационная панель `.object-focus`. Не заменять её фотографией только потому, что это умеет общий генератор.

## Формы и хранение

- `CONFIG`: бренд Dis Cleaning, телефон `+77076203813`, WhatsApp `77076203813`, регион Алматы. `webhookUrl` пуст; локальная копия включена.

- `server.js` запускается через `npm start` на 8080, обслуживает статику и простые `/api/order`, `/api/leads`; `server.py` — альтернативный сервер. Публичная форма сейчас не вызывает `/api/order`.
- Это не готовая защищённая CRM. Не включать новую серверную доставку, публикацию панели или webhook попутно с интерфейсной правкой. Данные клиентов не включать в эталоны, скриншоты или коммиты.

## Скрипты: что нельзя перепутать со сборкой

`npm start` не генерирует страницы. У сайта нет обязательной сборки перед запуском.

- `tools/build_catalog.py` — действующий, но массовый генератор: 72 внутренние публичные страницы плюс секция `#objects` на главной. Остальные секции главной сохраняет. Новые ручные изменения внутренних страниц может стереть.
- `tools/sync_layout.py` / `npm run sync-layout` — синхронизация общих блоков, не отдельных текстов или функций.
- `tools/refresh_homepage.py`, `style_home_features.py`, `build_index_html.py`, `build_all_service_pages.py`, `build_js.py`, `build_perfect_css.py`, `generate_dis_cleaning_theme.py`, `unify_styles_and_fix_all.py`, `update_*`, `inject_*`, `refine_*`, `install_*`, `process_*` и загрузчики изображений — миграции/исторические преобразования. Их повторный запуск не является штатным шагом. Даже идемпотентный декоратор может изменить принятую основу.
- Старые проверки `verify_*`, `audit_i18n.py` и прочие утилиты могут опираться на прежнюю структуру. Актуальные проверки публичного сайта: `audit_public.py` и `tests/`.

При добавлении функционала в генерируемые страницы сначала понять соответствие HTML и шаблона. Сохранить функцию и в источнике генерации, и в нужных HTML. Не запускать массовую генерацию, пока она может затереть другие наработки.

## Проверки

SEO-настройки находятся в `seo.config.json`, точечное применение — `tools/seo.py` (по умолчанию только отчёт, запись через `--apply`). Без подтверждённого домена доменные метаданные и sitemap не изменяются. Действующий генератор использует тот же SEO-обработчик; его запуск для SEO не требуется. Порядок настройки и проверки: `SEO.md`. Регион действующего сайта и переводов — только Алматы.

`python -m unittest discover -s tests -p "test_seo.py"` проверяет SEO на временных копиях страниц, включая сохранение тела и цен, домен, верификацию, sitemap и повторное применение. Браузерная проверка `tests/seo.spec.js` проверяет географию после переключения RU/KZ.

`python tools/audit_public.py` проверяет все публичные локальные ссылки, якоря, ресурсы, JSON-LD, номера контактов и отсутствие ранее удалённых блоков.

`npm test` запускает Playwright: все публичные страницы на 320, 390, 768, 1024, 1440, 1920 px; JavaScript и загрузку ресурсов; заявку с перехватом WhatsApp; слайдер, язык, меню, FAQ, фокус и географию RU/KZ. Панель администратора и серверная CRM этим набором полноценно не проверяются.

Тест `Visual review artifacts` сохраняет снимки в игнорируемую папку `artifacts/`, но не сравнивает пиксели с эталоном. Успешные тесты не дают права менять дизайн вне задачи.
